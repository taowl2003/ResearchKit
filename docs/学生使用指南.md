## 第一部分：首次连接与准备

### 入门一：向教师取得三样信息

1. **自己的服务器账号和当前密码**。文中的 `ly` 是教师、`test` 是示例学生；你始终使用教师给你的账号，不要登录别人的账号。
2. **服务器地址、SSH 端口和首次主机指纹**。启动器默认地址 `125.220.134.194`、端口 `8222`，以教师通知为准；校外是否要 VPN 也先确认。
3. **可用研究 Python 解释器的完整路径**，或者允许你在自己的服务器账号创建研究环境。网页能打开不代表 CNN 环境已经准备好。

服务器服务安装、账号开通和公共数据权限由管理员准备，学生无需安装平台服务或取得 sudo 权限。账号密码单独传递，不写在公共学生包里。首次连接后生成的 `connection.json` 和私钥属于你自己，整份个人连接文件夹不要转发。

### 入门二：在 Windows 第一次打开网页

1. 把学生包完整解压到有写权限的位置，例如桌面。进入 **启动器** 文件夹，双击 **Start-ResearchKit.cmd**。
2. 如果没有现成 SSH 别名，在“已有 SSH 别名”处直接回车。不要把用户名填成别名，也不要凭空填写 `svr-dl-test`；这样的名字必须先在本机 SSH 配置里定义才有效。
3. 按提示填自己的服务器账号；地址和端口正确时回车使用默认值，否则填教师给的值。
4. 启动器为本机生成专用密钥。密钥口令可以设置，也可以回车留空；它与服务器账号密码不同。首次主机指纹向教师核对后再确认。
5. 出现 `password` 提示时输入**服务器账号当前密码**，输入时不显示字符。启动器会把本机公钥登记到你自己的账号，再验证并打开网页。
6. 看网页顶部是否为自己的账号。保留黑色连接窗口，可以最小化；关掉它会断开网页，但不会删除项目。

以后双击同一个 **Start-ResearchKit.cmd** 即可。换电脑时，重新解压公共学生包、用自己的账号做首次配置；无需拷贝旧电脑的私钥。需要改账号时，用另一份干净解压目录配置，避免覆盖原账号的连接。

**没有 ssh.exe 怎么办：**在 Windows“设置”搜索“可选功能”，安装 **OpenSSH 客户端**，无需安装 OpenSSH 服务器。系统若要求本机管理员，请电脑管理员安装；日常启动不用管理员权限。[Microsoft 安装说明](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse)。服务器禁止密码登录时，教师需协助登记 `.pub` 公钥，不发送私钥。

**这一步改了什么：**只在解压目录生成个人连接设置和密钥，并向自己的服务器账号登记公钥；不改个人项目、案例或数据。启动器不会为你建立 Python 研究环境。

### 入门三：让 IDE 打开同一个服务器项目

已经使用 Cursor、Antigravity 或 VS Code 远程连接服务器的同学，可以继续原来的工具。没有 IDE 时，可安装 [VS Code](https://code.visualstudio.com/)，再安装 Remote - SSH、Python、Python Debugger 扩展。不同 IDE 的扩展兼容情况以当前版本为准，不必为了教程更换已有工具。

1. 先按下一部分的 **1.1** 在网页创建个人项目，展开项目，记下实际服务器目录；通常在 `~/researchkit-workspace/projects/` 下。
2. 在 IDE 的 Remote-SSH“连接到主机／新增主机”中填自己的连接信息，服务器系统选 Linux。不要打开 Windows 解压目录、平台源码目录或教师目录。
3. 如果 IDE 识别不了启动器专用密钥，在 **启动器/connection.json** 查看 `identityFile`，让 IDE 使用这个密钥路径。这个文件首次配置后才出现，不是公共包漏发。
4. 可参考 **辅助文件/ssh-config.example** 填一份自己的 SSH 配置，让 IDE 使用；不要覆盖已有配置，也不要把别人的 `User` 和密钥路径照抄过来。启动器本身无需手改全局 SSH 设置。
5. 远程连接后，用“打开文件夹”打开网页显示的个人项目实际目录。网页与 IDE 看到的是同一份服务器文件，保存代码后网页刷新即可看到，不需要下载再上传。

### 入门四：选择自己的 Python 环境

在 IDE 编辑器打开 `case.py`，按 **Ctrl+Shift+P → Python: Select Interpreter**。已有 Conda 环境在列表里就选它；没有时选“输入解释器路径”，填写教师给出的完整 Python 路径，不能只填环境文件夹。命令不存在时先确认当前远程窗口已启用 Python 扩展。

在服务器 IDE 终端核对：

```bash
python -c "import sys, yaml; print(sys.executable); print(sys.version); print(yaml.__version__)"
```

至少需要 **Python 3.11 和 PyYAML**。终端 `python` 与 IDE 选择的解释器可能不同；不确定时，把命令中的 `python` 换成教师提供的完整路径。不要因为看到 `(base)` 就认定环境正确。其他用户不能默认使用 LY 的私人 Conda 环境，也不要向平台服务的 Python 环境安装科研依赖。

如果自己账号已有 Conda，且教师允许准备个人环境，可在**服务器终端**运行：

```bash
conda create -n researchkit-student python=3.11 pip -y
conda activate researchkit-student
python -m pip install "PyYAML>=6,<7"
python -c "import sys; print(sys.executable)"
```

把最后输出的解释器路径选入 IDE。没有 Conda 或不能下载依赖时，请教师提供环境，不要对系统 Python 安装软件。

CNN 还需 NumPy、Matplotlib、PyTorch。优先选教师验证过的 GPU 环境；允许自行安装时，按 [PyTorch 安装选择器](https://pytorch.org/get-started/locally/)选择**服务器 Linux 和匹配驱动的 CUDA 版本**。Windows 本机没有 GPU，不代表服务器要装 CPU 版；不要自行安装服务器驱动。`辅助文件/requirements-cnn-extra.txt` 不替你决定 PyTorch 版本。只读的 `check-environment.py --cnn` 可以检查所选环境；包内辅助文件在 Windows，需放到自己的服务器目录后才能在服务器运行。

### 1.3 IDE 写入降雨算法实现

在 IDE 打开 `rainfall-framework/algorithms/scale/plugin.py`，用以下**完整文件**替换接口骨架并保存。代码来自教程中的降雨算法参考实现；这里的编辑发生在自己的项目目录中。

<!-- BEGIN TUTORIAL: rainfall-plugin -->
```python
"""读取只读降雨记录，按方案倍率缩放，另存处理结果与图表。"""
from __future__ import annotations

import csv
import io
import math
from pathlib import Path
from zipfile import ZipFile


def _parameters(context):
    # 案例参数描述数据来源；它们与下面的算法倍率参数分开管理。
    values = context.parameters
    source = values.get('data_source', 'local')
    dataset_id = values.get('dataset_id', '')
    root = values.get('data_root', 'sample-data')
    data_format = values.get('data_format', 'directory')
    if source not in {'local', 'dataset'}:
        raise ValueError('data_source 必须是 local 或 dataset')
    if data_format not in {'directory', 'zip'}:
        raise ValueError('data_format 必须是 directory 或 zip')
    if not isinstance(dataset_id, str) or not isinstance(root, str):
        raise ValueError('dataset_id 和 data_root 必须是字符串')
    return source, dataset_id, root, data_format


def _local_path(context, root: str, filename: str) -> Path:
    candidate = (Path(context.case_dir) / root / filename).resolve()
    case_dir = Path(context.case_dir).resolve()
    if case_dir not in candidate.parents:
        raise ValueError('本地数据路径必须位于项目目录内')
    return candidate


def _read_rows(context):
    source, dataset_id, root, data_format = _parameters(context)
    # 单文件托管版本使用 data.bin；原始目录数据保留 rainfall.csv 等文件名。
    # open_dataset 按已加入项目的准确版本只读访问，不复制或修改源数据。
    filename = context.parameters.get('data_file', 'rainfall.csv')
    if (not isinstance(filename, str) or not filename or
            Path(filename).is_absolute() or '..' in Path(filename).parts):
        raise ValueError('data_file 必须是数据集内的相对文件路径')
    if source == 'dataset':
        if not dataset_id:
            raise ValueError('dataset 模式必须填写 dataset_id')
        if data_format == 'directory':
            relative = '/'.join(part for part in (root.strip('/'), filename) if part)
            with context.open_dataset(dataset_id, relative, mode='r') as stream:
                return list(csv.DictReader(stream))
        with context.open_dataset(dataset_id, 'data.bin', mode='rb') as stream:
            with ZipFile(io.BytesIO(stream.read())) as archive:
                with archive.open(filename) as raw:
                    return list(csv.DictReader(io.TextIOWrapper(raw, encoding='utf-8')))

    if data_format == 'directory':
        with _local_path(context, root, filename).open(encoding='utf-8', newline='') as stream:
            return list(csv.DictReader(stream))
    with ZipFile(_local_path(context, root, '').with_suffix('.zip')) as archive:
        with archive.open(filename) as raw:
            return list(csv.DictReader(io.TextIOWrapper(raw, encoding='utf-8')))


def _svg(rows):
    # 生成无需额外绘图库的 SVG；坐标单位与数据中的毫米一致。
    values = [row['scaled_rainfall_mm'] for row in rows]
    maximum = max(values) if values else 1.0
    width, height, pad = 640, 260, 42
    step = (width - 2 * pad) / max(1, len(values) - 1)
    points = []
    for index, value in enumerate(values):
        x = pad + index * step
        y = height - pad - (value / maximum) * (height - 2 * pad)
        points.append(f'{x:.1f},{y:.1f}')
    labels = ''.join(f'<text x="{pad + index * step:.1f}" y="{height - pad + 18}" text-anchor="middle" font-size="11">{row["day"]}</text>'
                     for index, row in enumerate(rows))
    y_labels = ''.join(f'<text x="{pad - 8}" y="{height - pad - value / maximum * (height - 2 * pad) + 4:.1f}" text-anchor="end" font-size="11">{value:.1f}</text>'
                       for value in (0.0, maximum / 2, maximum))
    return f'''<svg xmlns="http://www.w3.org/2000/svg" width="{width}" height="{height}" viewBox="0 0 {width} {height}">
<rect width="100%" height="100%" fill="white"/><path d="M {pad} {pad} V {height-pad} H {width-pad}" stroke="#274c77" fill="none"/>
<polyline points="{' '.join(points)}" fill="none" stroke="#1d70a2" stroke-width="3"/>{labels}{y_labels}
<text x="{width / 2:.1f}" y="{height - 2}" text-anchor="middle" font-size="12">day</text><text x="14" y="{height / 2:.1f}" text-anchor="middle" font-size="12" transform="rotate(-90 14 {height / 2:.1f})">rainfall (mm)</text><text x="{pad}" y="24" font-size="16">Processed rainfall (mm)</text></svg>'''


def run(inputs, parameters, context):
    if inputs != {}:
        raise ValueError('scale 不接受输入端口')
    # parameters 是算法参数：默认值、项目值、方案值已经按顺序合并。
    factor = parameters['factor']
    if not isinstance(factor, (int, float)) or isinstance(factor, bool) or not math.isfinite(factor):
        raise ValueError('factor 必须是有限数值')
    rows = []
    for row in _read_rows(context):
        day = row.get('day', '')
        try:
            rainfall = float(row['rainfall_mm'])
        except (KeyError, TypeError, ValueError) as exc:
            raise ValueError('rainfall.csv 需要 day 和 rainfall_mm 列') from exc
        if not math.isfinite(rainfall):
            raise ValueError('rainfall_mm 必须是有限数值')
        rows.append({'day': day, 'rainfall_mm': rainfall, 'scaled_rainfall_mm': rainfall * factor})
    if not rows:
        raise ValueError('rainfall.csv 不可为空')
    # 原始总量和平均值用于核对；scaled_total 才是倍率处理后的总量。
    raw_total = sum(row['rainfall_mm'] for row in rows)
    summary = {'count': len(rows), 'raw_total': raw_total, 'raw_mean': raw_total / len(rows),
               'scaled_total': sum(row['scaled_rainfall_mm'] for row in rows), 'factor': factor}
    output = io.StringIO()
    writer = csv.DictWriter(output, fieldnames=['day', 'rainfall_mm', 'scaled_rainfall_mm'])
    writer.writeheader(); writer.writerows(rows)
    # 产物写入方案结果目录；原 CSV 不变，也不会自动成为平台数据资源。
    context.atomic_write_text(context.result_path('processed_rainfall.csv'), output.getvalue())
    context.atomic_write_text(context.result_path('rainfall_chart.svg'), _svg(rows))
    return {'summary': summary}
```

```python
"""项目内的 MNIST 手写数字十分类 CNN，使用用户已有数据，不自动下载。

通过 context.open_dataset 读取已授权的只读数据，也可显式指定本地数据目录。
训练集和测试集分别读取；结果、图表和模型只写入当前实验的产物目录。
"""
from __future__ import annotations

import csv
import io
import json
import os
from pathlib import Path
import random
import struct
import tempfile
import time
from typing import BinaryIO

import matplotlib

matplotlib.use('Agg')
import matplotlib.pyplot as plt
import numpy as np
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset


_IDX_FILES = {
    'train_images': 'train-images-idx3-ubyte',
    'train_labels': 'train-labels-idx1-ubyte',
    'test_images': 't10k-images-idx3-ubyte',
    'test_labels': 't10k-labels-idx1-ubyte',

class _MnistCnn(nn.Module):
    """两组卷积、ReLU和池化提取特征，再由全连接层输出十个类别分数。"""

    def __init__(self) -> None:
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(1, 16, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
            nn.Conv2d(16, 32, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
        )
        # 28×28图像经两次二倍池化变成7×7，最后一层输出未经Softmax的分数。
        self.classifier = nn.Sequential(
            nn.Flatten(),
            nn.Linear(32 * 7 * 7, 64),
            nn.ReLU(),
            nn.Linear(64, 10),
        )

    def forward(self, values: torch.Tensor) -> torch.Tensor:
        return self.classifier(self.features(values))


def _positive_int(parameters: dict, name: str) -> int:
    value = int(parameters[name])
    if value < 1:
        raise ValueError(f'{name} 必须是正整数')
    return value


def _resolve_device(value: object) -> torch.device:
    requested = str(value)
    # auto 优先使用当前解释器能访问的 GPU；显式 cuda 不可用时直接报错。
    if requested == 'auto':
        return torch.device('cuda' if torch.cuda.is_available() else 'cpu')
    if requested == 'cpu':
        return torch.device('cpu')
    if requested == 'cuda':
        if not torch.cuda.is_available():
            raise RuntimeError('方案指定 device=cuda，但当前 Python 环境没有可用 CUDA GPU')
        return torch.device('cuda')
    raise ValueError('device 只能是 auto、cpu 或 cuda')


def _seed_everything(seed: int) -> None:
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    if torch.cuda.is_available():
        torch.cuda.manual_seed_all(seed)
    # 固定种子和卷积策略，便于教学比较；不同PyTorch/CUDA版本仍可能有差异。
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False


def _read_exact(stream: BinaryIO, size: int, label: str) -> bytes:
    value = stream.read(size)
    if len(value) != size:
        raise ValueError(f'{label} 长度不足：需要 {size} 字节，实际 {len(value)} 字节')
    return value


def _load_idx_images(stream: BinaryIO, limit: int, label: str) -> np.ndarray:
    # IDX采用大端整数头；先验证格式和样本数，再读取指定数量的28×28图像。
    magic, count, rows, columns = struct.unpack('>IIII', _read_exact(stream, 16, label))
    if magic != 2051 or (rows, columns) != (28, 28):
        raise ValueError(f'{label} 不是 28×28 的 MNIST 图像 IDX 文件')
    if limit > count:
        raise ValueError(f'{label} 只有 {count} 个样本，不能请求 {limit} 个')
    raw = _read_exact(stream, limit * rows * columns, label)
    return np.frombuffer(raw, dtype=np.uint8).copy().reshape(limit, 1, rows, columns)


def _load_idx_labels(stream: BinaryIO, limit: int, label: str) -> np.ndarray:
    magic, count = struct.unpack('>II', _read_exact(stream, 8, label))
    if magic != 2049:
        raise ValueError(f'{label} 不是 MNIST 标签 IDX 文件')
    if limit > count:
        raise ValueError(f'{label} 只有 {count} 个标签，不能请求 {limit} 个')
    labels = np.frombuffer(_read_exact(stream, limit, label), dtype=np.uint8).copy()
    if np.any(labels > 9):
        raise ValueError(f'{label} 包含非十分类标签')
    return labels


def _local_root(context) -> Path:
    root = str(context.parameters.get('data_root', '')).strip()
    if not root:
        raise ValueError('data_source=local 时必须在方案中明确填写绝对 data_root')
    path = Path(root).expanduser()
    if not path.is_absolute():
        raise ValueError('data_root 必须是显式绝对路径')
    if not path.is_dir():
        raise ValueError(f'本地 MNIST 数据目录不存在：{path}')
    raw = path / 'raw'
    return raw if raw.is_dir() else path


def _read_local_file(root: Path, filename: str):
    path = root / filename
    if not path.is_file() or path.is_symlink():
        raise ValueError(f'本地 MNIST 文件不存在或不是普通文件：{path}')
    return path.open('rb')


def _load_split(context, *, split: str, limit: int) -> tuple[np.ndarray, np.ndarray]:
    if split not in {'train', 'test'}:
        raise ValueError(f'未知数据划分：{split}')
    # 官方 train 和 t10k 是两个独立数据划分，不能把测试样本混进训练。
    image_name = _IDX_FILES[f'{split}_images']
    label_name = _IDX_FILES[f'{split}_labels']
    source = str(context.parameters.get('data_source', '')).strip()
    if source == 'dataset':
        dataset_id = str(context.parameters.get('dataset_id', '')).strip()
        if not dataset_id:
            raise ValueError('data_source=dataset 时必须在方案中填写已授权的 dataset_id')
        with context.open_dataset(dataset_id, f'raw/{image_name}', mode='rb') as image_stream:
            images = _load_idx_images(image_stream, limit, f'{split} 图像')
        with context.open_dataset(dataset_id, f'raw/{label_name}', mode='rb') as label_stream:
            labels = _load_idx_labels(label_stream, limit, f'{split} 标签')
    elif source == 'local':
        root = _local_root(context)
        with _read_local_file(root, image_name) as image_stream:
            images = _load_idx_images(image_stream, limit, f'{split} 图像')
        with _read_local_file(root, label_name) as label_stream:
            labels = _load_idx_labels(label_stream, limit, f'{split} 标签')
    else:
        raise ValueError("data_source 必须是 'dataset' 或 'local'")
    if len(images) != len(labels):
        raise ValueError(f'{split} 图像和标签数量不一致')
    return images, labels

def _evaluate(model: nn.Module, loader: DataLoader, device: torch.device):
    # 评估不更新模型参数；CrossEntropyLoss接收原始分数，Softmax只用于置信度。
    model.eval()
    loss_fn = nn.CrossEntropyLoss(reduction='sum')
    total_loss = 0.0
    total = 0
    correct = 0
    predictions: list[tuple[int, int, float]] = []
    with torch.no_grad():
        for images, labels in loader:
            images, labels = images.to(device), labels.to(device)
            logits = model(images)
            total_loss += float(loss_fn(logits, labels).item())
            probabilities = torch.softmax(logits, dim=1)
            confidence, predicted = torch.max(probabilities, dim=1)
            correct += int((predicted == labels).sum().item())
            total += int(labels.numel())
            predictions.extend(
                (int(true), int(pred), float(score))
                for true, pred, score in zip(labels.cpu(), predicted.cpu(), confidence.cpu())
            )
    return total_loss / max(total, 1), correct, total, predictions


def run(inputs, parameters, context):
    """按当前方案训练分类器，记录测试指标，并保存供审核和比较的产物。"""
    if inputs != {}:
        raise ValueError('mnist.cnn 不接收算法输入；数据源由案例方案参数指定')
    epochs = _positive_int(parameters, 'epochs')
    batch_size = _positive_int(parameters, 'batch_size')
    train_limit = _positive_int(parameters, 'train_limit')
    test_limit = _positive_int(parameters, 'test_limit')
    num_workers = int(parameters['num_workers'])
    if num_workers < 0:
        raise ValueError('num_workers 不能小于 0')
    learning_rate = float(parameters['learning_rate'])
    if not 0.0 < learning_rate <= 10.0:
        raise ValueError('learning_rate 必须在 (0, 10] 内')
    seed = int(parameters['seed'])
    device = _resolve_device(parameters['device'])
    _seed_everything(seed)
    started = time.monotonic()

    train_images, train_labels = _load_split(context, split='train', limit=train_limit)
    test_images, test_labels = _load_split(context, split='test', limit=test_limit)
    # 像素从0—255归一化为0—1；保持训练、测试样本相互独立。
    train_tensor = torch.from_numpy(train_images).to(torch.float32).div_(255.0)
    test_tensor = torch.from_numpy(test_images).to(torch.float32).div_(255.0)
    train_targets = torch.from_numpy(train_labels.astype(np.int64, copy=False))
    test_targets = torch.from_numpy(test_labels.astype(np.int64, copy=False))
    train_dataset = TensorDataset(train_tensor, train_targets)
    test_dataset = TensorDataset(test_tensor, test_targets)
    train_generator = torch.Generator().manual_seed(seed)
    loader_options = {'batch_size': batch_size, 'num_workers': num_workers, 'pin_memory': device.type == 'cuda'}
    # 只打乱训练集；测试集保持原顺序，预测表中的样本索引才可对应。
    train_loader = DataLoader(train_dataset, shuffle=True, generator=train_generator, **loader_options)
    test_loader = DataLoader(test_dataset, shuffle=False, **loader_options)

    model = _MnistCnn().to(device)
    optimizer = torch.optim.Adam(model.parameters(), lr=learning_rate)
    loss_fn = nn.CrossEntropyLoss()
    history: list[dict] = []
    # 每轮：训练前向计算→损失→反向传播→更新权重，再评估测试指标。
    # 测试指标用于演示比较；正式调参应另设验证集，最终测试集不参与调参。
    for epoch in range(1, epochs + 1):
        model.train()
        weighted_loss = 0.0
        seen = 0
        for images, labels in train_loader:
            images, labels = images.to(device), labels.to(device)
            optimizer.zero_grad(set_to_none=True)
            logits = model(images)
            loss = loss_fn(logits, labels)
            loss.backward()
            optimizer.step()
            batch_count = int(labels.numel())
            weighted_loss += float(loss.item()) * batch_count
            seen += batch_count
        test_loss, correct, total, _ = _evaluate(model, test_loader, device)
        history.append({
            'epoch': epoch,
            'train_loss': weighted_loss / max(seen, 1),
            'test_loss': test_loss,
            'test_accuracy': correct / max(total, 1),
        })

    test_loss, correct, total, predictions = _evaluate(model, test_loader, device)
    # 混淆矩阵的行是真实类别、列是预测类别，便于找出容易混淆的数字。
    confusion = np.zeros((10, 10), dtype=np.int64)
    for true, predicted, _confidence in predictions:
        confusion[true, predicted] += 1
    elapsed = time.monotonic() - started
    summary = {
        'algorithm': 'mnist.cnn@1.0.0',
        'accuracy': float(correct / max(total, 1)),
        'correct_count': int(correct),
        'test_samples': int(total),
        'train_samples': int(len(train_dataset)),
        'test_loss': float(test_loss),
        'epochs': int(epochs),
        'learning_rate': float(learning_rate),
        'batch_size': int(batch_size),
        'seed': int(seed),
        'device': str(device),
        'elapsed_seconds': float(elapsed),
        'artifacts': [
            'metrics.json', 'history.csv', 'predictions.csv', 'confusion_matrix.csv',
            'artifacts/training_curve.png', 'artifacts/confusion_matrix.png', 'artifacts/checkpoint.pt',
        ],
    }
    # context路径接口将表格、图和模型放到本方案当前批次；不修改MNIST原数据。
    context.atomic_write_json(context.result_path('metrics.json'), {'summary': summary, 'history': history})
    _write_csv(
        context,
        'history.csv',
        ['epoch', 'train_loss', 'test_loss', 'test_accuracy'],
        ((row['epoch'], row['train_loss'], row['test_loss'], row['test_accuracy']) for row in history),
    )
    _write_csv(
        context,
        'predictions.csv',
        ['sample_index', 'true_label', 'predicted_label', 'confidence'],
        ((index, true, predicted, confidence) for index, (true, predicted, confidence) in enumerate(predictions)),
    )
    _write_csv(
        context,
        'confusion_matrix.csv',
        ['true_label'] + [f'predicted_{label}' for label in range(10)],
        ((label, *confusion[label].tolist()) for label in range(10)),
    )
    _plot_history(history, context)
    _plot_confusion(confusion, context)
    _save_checkpoint(context, model, summary)
    return {'summary': summary}
```

```python
    seed = int(parameters.get('seed', 2026))
    ping_count = int(parameters.get('ping_count', 10))
    noise_std = float(parameters.get('noise_std_s', 0.0))

    # 固定随机种子，让两套声速方案使用完全相同的目标和观测。
    rng = random.Random(seed)
    truth_points = [
        (rng.uniform(-220.0, 260.0), rng.uniform(-210.0, 250.0), rng.uniform(45.0, 110.0))
        for _ in range(ping_count)
    ]

    receivers = _DEFAULT_RECEIVERS
    measurements, truth = [], []
    for index, point in enumerate(truth_points, start=1):
        ping_id = f"P{index:02d}"
        # 以第一个水听器为参考，将距离差除以真实声速得到时差。
        ranges = [math.dist(point, recv) for recv in receivers]
        tdoa_list = []
        for r_idx in range(1, len(receivers)):
            ideal = (ranges[r_idx] - ranges[0]) / sound_speed
            tdoa_list.append(ideal + rng.gauss(0.0, noise_std) if noise_std > 0 else ideal)
        measurements.append({"ping_id": ping_id, "tdoa": tdoa_list})
        truth.append({"ping_id": ping_id, "x_m": point[0], "y_m": point[1], "z_m": point[2]})

    sim_data = {
        "receivers": receivers,
        "measurements": measurements,
        "truth": truth,
        "sound_speed_m_s": sound_speed
    }
    # 留下本次仿真的观测和真值，供网页查看、核对及另存为个人数据。
    context.atomic_write_json(context.result_path('simulation.json'), sim_data)
    return {"sim_data": sim_data}
```

#### 3. 定位求解算子实现（`algorithms/locator/plugin.py`）
<!-- BEGIN TUTORIAL: acoustic-modular-locator-plugin -->
```python
"""三维水声定位解算与评估算子：根据时差方程求解声源三维坐标，并评估定位误差。"""
from __future__ import annotations
import csv
import io
import math

def _solve(matrix, vector):
    size = len(vector)
    augmented = [list(map(float, row)) + [float(val)] for row, val in zip(matrix, vector)]
    for col in range(size):
        pivot = max(range(col, size), key=lambda r: abs(augmented[r][col]))
        if abs(augmented[pivot][col]) < 1e-10:
            raise ValueError('阵列或时差方程退化，无法定位')
        augmented[col], augmented[pivot] = augmented[pivot], augmented[col]
        factor = augmented[col][col]
        augmented[col] = [v / factor for v in augmented[col]]
        for row in range(size):
            if row != col:
                scale = augmented[row][col]
                augmented[row] = [a - scale * b for a, b in zip(augmented[row], augmented[col])]
    return [row[-1] for row in augmented]

def _estimate(receivers, tdoa_list, sound_speed):
    ref = receivers[0]
    matrix, vector = [], []
    for idx, recv in enumerate(receivers[1:]):
        dist_diff = tdoa_list[idx] * sound_speed
        row = [2.0 * (recv[ax] - ref[ax]) for ax in range(3)] + [2.0 * dist_diff]
        right = sum(v*v for v in recv) - sum(v*v for v in ref) - dist_diff*dist_diff
        matrix.append(row); vector.append(right)
    # 四个未知量为三维坐标和参考接收点距离，至少需要本例的五个接收点。
    x, y, z, _ = _solve(matrix, vector)
    return x, y, z

def run(inputs: dict, parameters: dict, context) -> dict:
    if 'bearing_data' not in inputs:
        raise ValueError('locator 必须接收 bearing_data 输入端口')
    data = inputs['bearing_data']
    sound_speed = float(parameters.get('sound_speed_m_s', 1500.0))
    truth_map = {t['ping_id']: (t['x_m'], t['y_m'], t['z_m']) for t in data['truth']}
    rows = []
    for item in data['measurements']:
        tx, ty, tz = truth_map[item['ping_id']]
        x, y, z = _estimate(data['receivers'], item['tdoa'], sound_speed)
        err = math.dist((x, y, z), (tx, ty, tz))
        rows.append({'ping_id': item['ping_id'], 'x_m': x, 'y_m': y, 'z_m': z,
                     'true_x_m': tx, 'true_y_m': ty, 'true_z_m': tz, 'error_m': err})

    # 使用已知仿真真值评估误差；实际无真值数据不能直接套用此指标。
    rmse = math.sqrt(sum(r['error_m']**2 for r in rows) / len(rows))
    summary = {'count': len(rows), 'rmse_m': rmse, 'max_error_m': max(r['error_m'] for r in rows), 'sound_speed_m_s': sound_speed}

    output = io.StringIO()
    writer = csv.DictWriter(output, fieldnames=['ping_id', 'x_m', 'y_m', 'z_m', 'true_x_m', 'true_y_m', 'true_z_m', 'error_m'])
    writer.writeheader(); writer.writerows(rows)
    context.atomic_write_text(context.result_path('localized_trajectory.csv'), output.getvalue())
    return {'summary': summary}
```

#### 场景 2：如果改进了算法（加入多普勒或海洋环境参数），契约怎么变？
- **平滑兼容扩充**：在 `sim_data` 中新增字段（如 `sim_data['doppler_hz'] = ...`），契约仍为 `mapping@1.0.0`，算法版本升为 `1.1.0`。仅当旧字段含义、类型和单位都保持兼容时，下游旧算子才可不改；mapping 只保证对象类型，不能代替字段语义检查。
- **发布入库血缘继承**：提交审核时，发布模式选择 **“作为已有资源的新版本”**，父版本（`parent_ref`）选择 `acoustic.simulator@1.0.0`。平台会自动将其归入同一算法家族族谱中。

## 参考三：IDE 断点调试与多方案启动

### 核心原理与设计规范

1. **为什么不能直接 F5 运行 `plugin.py`？**
   - 项目中的算法（如 `algorithms/cnn/plugin.py`）属于算子模块，通过 `context` 由框架调用，内部没有 `if __name__ == '__main__':`。
   - 直接运行 `plugin.py` 通常只加载函数定义，不会完成一次案例实验；应由入口准备参数与上下文后调用。
2. **正确的调试入口**：
   - 调试入口始终是项目根目录的 `run_experiment.py`。
   - **断点直接打在算法源代码内部**（如 `algorithms/cnn/plugin.py` 的模型前向传播或反向传播代码行）。
   - 启动 `run_experiment.py` 后，平台调度器执行到该算子时会自动挂起，支持变量查看、张量形状（Tensor Shape）与单步调试（F10/F11）。

### 常见问题

- **CNN却去读取降雨CSV**：检查方案的 `case_parameters.algorithm_alias` 是否为 `cnn`，`dataset_id` 是否是本人网页中已加入项目的真实MNIST版本。复制现有正确方案后再改学习率，不从空参数开始。不要照抄别人的数据ID。

- **终端有 `(base)`，调试仍缺依赖**：终端环境与编辑器解释器可能不同，按第一部分“入门四”核对 `sys.executable`。

资源已经准备好后，日常工作通常只需在自己的项目目录中处理这些路径：

```text
case.py                                  当前案例入口（降雨/CNN 选择算法，水声连接三阶段）
algorithms/<别名>/plugin.py              可编辑的本地算法实现
algorithms/<别名>/plugin.yaml            本地算法名称、版本、参数与契约
```

```bash
python run_experiment.py --scheme factor-2

# 显式整理既有旧批次；仅用于已更新的标准辅助入口
```

新增一个只在当前项目使用的本地算法，也不必每次回网页新建个人算法资源。以首例已经有 `algorithms/scale/` 本地实现和 `mapping@1.0.0` 契约为例：

1. 在 IDE 复制目录 `algorithms/scale/` 为 `algorithms/scale_custom/`。
2. 修改副本的 `plugin.yaml`，把 `name` 改为 `rainfall.scale_custom`；再按研究需要编辑其 `plugin.py`。
3. 在已有 `project.yaml` 的 `plugins:` 下保留原有条目，并增加 `scale_custom` 的 `path: algorithms/scale_custom` 和所需 `parameters:`；把方案 YAML 中的 `case_parameters.algorithm_alias` 和 `algorithm_parameters` 的键改成 `scale_custom`。

例如，在原有 `plugins:` 下增加下面这段，缩进与原来的 `scale:` 相同；不要用它替换整个 `project.yaml`：

```yaml
  scale_custom:
    path: algorithms/scale_custom
    parameters:
      factor: 4
```

例如从 factor-2 复制为 `experiments/factor-4.yaml` 后，可把这份文件改为下面完整内容；文件名 `factor-4.yaml` 就是方案 ID，RAIN_ID 必须替换为网页实际登记的 ID：

```yaml
schema: researchkit.experiment/v1
name: 降雨倍率4
description: scale_custom 的倍率4练习
case_parameters:
  algorithm_alias: scale_custom
  data_source: dataset
  dataset_id: 替换成实际 RAIN_ID
  data_root: ''
  data_format: directory
  data_file: data.bin
algorithm_parameters:
  scale_custom:
    factor: 4
```

在 IDE 运行新方案：

```bash
python run_experiment.py --scheme factor-4
python run_experiment.py --compare factor-2 factor-4
```

若保留复制来的降雨实现，只将倍率改为4，新方案的 scaled_total 应为40。原有其他方案及其最新产物仍在。以后改 factor-4 的参数再运行，新运行成功后替换 factor-4 的旧成功产物；失败则保留旧成功结果。想长期对照两套参数，应另存为不同方案，而不是依赖同方案的历史运行。

这个例子只改项目内的本地算法目录和 YAML；不要改 `.researchkit/plugins/`、`.researchkit/contracts/`、`.researchkit/runtime/`、`task` 或 lock。它也不替代中央登记：加入共享数据、保存派生数据、固定提交、教师审核发布和权限分配目前仍要回网页完成。

整理测试资源时按后面的“整理资源”：平台案例先删，算法和数据检查案例引用；用户自己的目录由用户清理。**本教程不自动清空任何现有资源。** 框架与教学代码的开发源码统一维护在 examples/three-cases/，本指南的带同步标记代码片段从这些实现生成，网页创建表单保持空白。学生无需访问或复制该源码目录。
## 参考五：数据从哪里来，怎样加入和保存

### 保存个人数据或处理结果

原始数据不能原地修改。学生处理后得到的 CSV、文本或模型中间产物，应在 **数据资源** 选择本人项目中的产物保存为派生数据：

1. 在 **个人工作区 → 数据资源** 先用页面上方的**目标项目**下拉框选择本人项目，再选择 `results/factor-3/<批次ID>/processed_rainfall.csv`，填写名称 `test-降雨练习处理结果-v1`，保存为派生数据并记下派生数据 ID；派生数据默认仅提交者本人私有。保存会流式托管并中央登记，源文件仍在项目；随后在数据卡片“加入项目”的**单个目标项目下拉框**选择项目并直接加入，写入完整数据引用，不复制文件或自行授予权限。也可勾选卡片下方的“加入完整数据集”，使用页面上方的“将所选数据集加入项目”批量按钮；两种方式任选其一。
2. 将该派生数据加入项目并再次生成固定提交，使固定提交清单明确记录该派生数据版本引用。
3. LY 在 **教师管理 → 审核入库** 查看该固定提交的产物与引用后，可先 **复制到 ly 工作区测试** 并在自己的 IDE 验证，再根据教学与科研需要决定该私有派生数据是保留私有（`keep_private`）、纳入平台派生数据集（`publish_derived`）、提升为公共数据集（`promote_public`）或作为已有派生数据集的新版本（`new_version`）。


### 原始数据、私有数据、平台数据的区别

共享原始数据在 `/home/share/Datasets/`，只有经过教师登记并授予你权限，才出现在个人数据资源中。你只有只读访问权，不在这里修改、删除原文件。个人 CSV、切片、模型等处理产物，可以托管到 `/home/share/DerivedDatasets/`，默认仅本人可用；项目保存准确版本引用，不复制一份大数据。

“教师审核可读”只让教师在审核该提交时读取私有数据，不表示已经入库或公开。学生无需在个人页发布数据。教师在审核入库中决定保留私有还是纳入平台，入库后再授权给谁使用。

### 加入数据时选哪个控件

- **只加一个数据集：**在该数据卡片的目标项目下拉框选择项目，点旁边“加入项目”，不用勾“加入完整数据集”。
- **批量加多个：**勾各卡片“加入完整数据集”，再用页面上方的目标项目和“将所选数据集加入项目”。
- **从项目文件保存为新数据：**页面上方先选项目，才会列出“将项目文件保留为派生数据”的源文件。先在 IDE 保存文件，必要时重新选项目或刷新。

同一准确数据版本再次加入同一项目，不重复增加引用。托管的单文件示例读取名为 `data.bin`；共享目录数据按其 README 使用 `rainfall.csv`、`raw/...` 等原相对路径。不要把两者混用。

### 看完整 README、按标签查找和导出

数据条目默认只显示摘要。点“展开完整说明”看安全渲染的 Markdown，点“导出 README.md”保存原文。顶部多个标签默认取交集；不匹配当前交集的标签会不可选。筛选后“导出当前列表说明”生成匹配数据集说明汇编。

## 参考六：方案、产物与固定提交分别保存什么

**一套方案是一份 YAML 参数文件，不是另一份代码。** 案例参数和各算法参数一起保存在 `experiments/<方案ID>.yaml`。同一个方案运行成功后只留最新成功产物；需要长期对照就另存不同方案，不依赖同方案旧批次。

每次运行先写 `results/<方案ID>/<批次ID>/`，记录当时的 `parameters.json`、状态、摘要、报告与产物。成功后才整理旧批次；失败保留上一成功结果和最近一次错误、参数与报告。无法识别或运行中的目录不自动删。不要在 IDE 运行过程中手动删除批次目录。

**旧项目按钮在哪里：**个人工作区 → 项目 → 展开具体项目 → 提交小版本/大版本按钮下方 → 展开 **IDE 实验方案与产物**。旧标准辅助文件出现 **启用最新结果保存方式** 时，先结束 IDE 实验再点击；随后在 IDE 产物区点 **整理旧产物**。它不会改 case.py、方案或已提交版本。自定义过的辅助文件不会被自动覆盖；新项目已用新规则，不必找这两个升级按钮。

网页“固定提交”只看自己。固定提交把当时的代码、方案、所选小产物和数据引用复制进中央快照；之后改个人文件不改快照。大模型和大数据宜保存为托管数据引用，不把整个训练输出夹提交进去。网页不重新运行，也不自动证明产物与代码一致，提交前由本人核对，教师审核所保存内容。

## 参考七：整理资源，先分清平台与个人

管理员只整理平台里已经入库的案例、算法和已登记数据；学生的个人项目、私有算法与私有数据不在这个范围。平台资源可以向所有人开放，也可以只授权指定用户，这里的“平台资源”不是指必须全员公开。

| 在哪里操作 | 按钮 | 删除的内容与保留的内容 |
| --- | --- | --- |
| 教师管理 → 案例管理，展开某个版本 | 删除案例 | 删除平台案例副本，保留独立算法、数据、用户项目和固定提交 |
| 教师管理 → 算法管理，展开某个版本 | 删除算法 | 没有平台案例使用时，删除平台算法副本；学生已经复制进项目的代码不动 |
| 教师管理 → 数据管理，展开某个版本 | 移除数据登记 | 没有平台案例使用时，从平台默认资源列表移除；原始目录和派生数据文件都保留 |
| 个人工作区 → 项目 | 归档／删除本地副本 | 归档保留项目目录、实验方案和产物并可恢复；删除本地副本须确认后才物理删除该目录及其中产物，不会同时删除资源授权或中央固定提交 |

### 管理员删除一条平台资源

旧版本曾提供“下架”和“回收站”。这些状态只是停止新选用，案例本身仍在平台库中，所以它对算法和数据的引用仍然有效。当前管理页会把这些历史版本一并列出，并标注“已下架／回收站”；需要清掉时，仍在这一条版本下点“删除案例”。**不能因为案例已下架，就直接删除它依赖的算法或数据。**

若删算法时提示被某个案例使用，而您以为案例已经删完，请先回到案例管理刷新，按提示中的准确案例引用找该历史版本。确认不再需要后删除它，再回算法管理删除算法。管理列表读取失败时可能不完整，应先刷新，不要手工修改数据库或绕过引用检查。

1. 进入对应的案例、算法或数据管理页面，找到要删的准确名称和版本，展开这一行。
2. 点击删除按钮。算法和数据会先检查平台案例引用：如果有引用，会列出案例名称及版本，不能继续删除。只有当这些案例也确实不需要时，才先去案例管理删除它们，再回来删除算法或移除数据登记；不要为了删一条算法而顺手删掉仍有用的案例。
3. 核对确认区说明，再点确认按钮。页面会明确提示已删除或已移除哪个版本。

删除案例不需要先清理学生的个人项目。平台不修改学生的工作区和历史固定提交，也不连带删除案例用过的算法或数据。算法／案例都按准确版本操作，不是一次删掉全部版本。

### 数据磁盘文件留给管理员手动处理

网页里的 **移除数据登记** 只让这份数据退出平台默认选择列表，不会删除 `/home/share/Datasets` 中的目录，也不会删除托管派生数据文件。必要的来源、读取登记和既有授权保留，以免旧项目突然无法读取；后续扫描也不会自动将它恢复到默认资源列表。

操作成功后，网页显示该数据实际保留的位置和人工清理说明。如果还要释放磁盘空间，把路径交给服务器管理员逐项核对，决定是否手动删除。平台不自动执行删除文件命令。**手动删掉数据文件后，仍引用它的个人项目和历史版本就可能无法再运行**，因此不要只看文件名就删，也不要删除整个共享数据父目录。

### 一个简单的测试资源清理例子

假设要移除一套不用的“MNIST 测试案例”、`mnist.cnn@1.0.0` 算法和“测试预测结果”数据：

1. 在案例管理删除该测试案例的准确版本，保留日常使用的降雨案例与其它正式案例。
2. 在算法管理删除 `mnist.cnn@1.0.0`。如果提示还有别的案例使用它，先判断那些案例是否还要用；要用就保留算法。
3. 在数据管理移除“测试预测结果”的平台登记，保留真实原始 MNIST 数据以及其它科研数据。派生文件原地保留，有需要时再让服务器管理员按显示路径人工核对。
4. 各用户分别在自己的项目页归档或删除不需要的本地测试项目。已经保存的固定提交不在本次平台资源删除范围内。

日常管理不需要理解数据库文件引用数量，也不需要按整个项目连带清理。菜单中的资源数量表示本页平台资源及其版本数量，与中央数据库保存的历史文件数量不同。

### 删除任务与删除平台资源分别处理

- **删分发任务**：到“分发任务”，只移除这条分发记录在双方列表中的入口；资源、授权和已有个人项目保留。
- **删平台案例／算法，或移除数据登记**：到对应资源管理页面，仍按上面的资源删除规则检查平台案例依赖；不会顺带清理任务或用户工作区。
- **删个人项目**：由本人在个人“项目”中操作，不需要先删除任务或平台案例。

任务与平台资源可以分别整理，先删哪一项都不应使另一项的删除失败。算法和数据能否移除，仍以是否有平台案例引用为准。资源移除后，旧任务里保留的资源名称只是当时分发内容的历史说明，不代表资源重新入库；数据磁盘文件仍按上面的数据磁盘处理说明由管理员另行核对处理。

### 整理本人算法、数据和已归档项目

平台已经删掉资源，但个人区仍看到“历史任务保留资源”时，是以前获得的使用权和副本仍被保留，不代表重新入库。

1. **算法库**：展开不再使用的准确版本，点 **从我的算法库移除**。需要时勾选 **显示已移除算法**，再点该版本的 **恢复显示**。
2. **数据资源**：展开不再使用的数据，点 **从我的数据列表移除**。需要时勾选 **显示已移除数据**，再点 **恢复显示**。主列表和“可用派生数据”共用同一设置。
3. 上面两种“移除”只整理本人的列表，不撤销授权、不删除文件，也不影响已经加入项目的算法和数据；其他用户的列表不变。新建的个人本地算法还有独立的删除操作，核对后再使用。
4. **项目**：勾选 **显示已归档项目（磁盘文件仍保留）**。若确实不要该目录及其中产物，展开核对路径，点 **删除本地副本... → 确认删除本地副本**。归档只隐藏，删除确认后才实际删除目录；中央固定提交和资源授权保留。

个人派生数据的“仅本人可用”“教师审核可读”是读取范围，不表示已经成为平台公共资源。教师需要纳入平台时，到 **审核入库** 查看固定提交和数据，不在个人数据页发布。

| 管理员下架或删掉案例后，学生已有算法/数据还能用吗 | 可以；案例删除会自动将原有级联权限固化保存至独立授权，不影响学生已有项目继续运行与提交 |
| 管理员清了中央项目，学生个人页还能删本地副本吗 | 可以；本地查看与 **删除本地副本...** 不依赖中央项目记录仍存在 |
| 同一算法同一别名在项目里点两次加入会怎样 | 幂等返回既有绑定状态并保留你对项目内其它文件的个人修改 |
| 修改了受保护文件后再点加入算法提示依赖锁报错 | 正常安全拦截；添加算法前会先校验已有 `.researchkit/lock.json`，被篡改的项目不能通过加算法“洗白”重签锁 |
| 教师修改原案例中平台算法后审核入库没填新版本号 | 系统会识别代码与来源变动并强制要求发布为平台算法新版本；若与已有版本内容不同，同版本覆盖会被拒绝 |
| 审核入库提示缺少标签或说明 | v0.8 后端对所有新资源（含本地算法晋升、私有派生转入）强制校验非空 `tags` 与 `description`；`new_version` 需指定同类别有效父版本 |


| 现象 | 处理 |
| --- | --- |
| no such host is known | 未定义的 SSH 别名不是账号；用 Start-ResearchKit.cmd -Setup 在自己的连接目录重新配置真实主机、端口和用户名 |
| 找不到 IDE 实验方案与产物 | 在个人“项目”展开项目卡片，在提交按钮下方展开；不在 IDE 菜单和固定提交页里 |
| 找不到运行或检查按钮 | 网页不运行代码；用服务器 IDE 启动 run_experiment.py，网页只查看生成产物 |
| Python 缺 yaml / torch 或 GPU 不可用 | 检查当前研究解释器的 sys.executable 和依赖，不改平台服务环境或服务器驱动 |
| CNN 却读取降雨 CSV | 检查 cnn-* 方案的 algorithm_alias=cnn、dataset_id=实际 MNIST_ID；不要运行继承的降雨方案 |
| 声速两方案没有明显差异 | 确认 sim 始终1500且种子相同，仅 locator 分别1500/1480；打开两套方案的 parameters.json 核对 |

## 参考九：消息反馈与教师回复

网页能打开、但使用中发现问题时，不用离开平台找人：点击左侧 **消息反馈**。所有账号使用同一个入口；学生只能看到自己发起的反馈，管理员 `ly` 可以看到所有用户的反馈。

### 用户发一条反馈

1. 点击 **消息反馈**，填写一个容易辨认的标题，例如“降雨项目提交时提示数据不可读”。
2. 正文写清：在哪个页面、点了什么、看到什么提示、原本希望发生什么。可以把项目 ID、固定提交 ID、报错文字粘进去；不要发送密码、私钥或启动连接令牌。
3. 点击 **发送反馈**，看到发送成功后，在列表打开这条反馈即可查看对话。发送失败时文字会保留，可以重试；不要为了重试反复新建同一条反馈。

标题最多 120 字，正文最多 20000 字。当前支持文字，不上传附件，也不发送外部邮件。消息保存在平台中央存储；关闭启动器或更换电脑后，仍可用同一账号查看。

### 管理员处理并回复

1. `ly` 登录后点击同一个 **消息反馈**，列表会显示来源账号、主题、处理状态与未读提示。
2. 打开反馈，阅读问题；需要处理时将状态改为 **处理中**。
3. 在回复框填写处理结果或需要用户补充的信息，点击发送回复。处理完成后将状态改为 **已处理**。
4. 用户打开自己的反馈即可看到回复，也能继续补充文字；对已处理反馈追加问题，会重新变为 **待处理**。

### 用一次往返确认功能正常

`test` 发一条标题为“功能练习：消息反馈”的消息 → `ly` 查看并标记“处理中” → 回复“收到，已完成测试”并标记“已处理” → `test` 查看回复。左侧未读数字会随刷新更新；只有实际打开并展示过的消息才标为已读。较长对话可加载更早消息。

消息只在用户本人和管理员之间可见，其他学生不能浏览。即使反馈已处理，对话也保留，方便继续沟通；本版不提供删除消息或附件功能。
## 参考十：教师配合学生时要做什么

学生做到固定提交后，教师在“审核入库”看所选代码、方案和产物；需要试用可复制到 LY 个人区，用自己的 IDE 测试。案例最多一个，算法和私有数据可勾多个；填写或继承准确版本、标签和说明，再预览和确认。继承且未改动的平台算法、原始数据无需重复入库。

入库之后，在案例管理授权准确案例版本，会级联授权它依赖的平台算法与数据；学生在“项目”用这个案例作起始模板创建个人副本。教师也可以单独授权算法或数据，学生自行加入已有项目。权限本身不会创建个人项目或复制大数据。

新增共享原始数据时，数据维护者把数据放进 `/home/share/Datasets/` 下合适的目录，用该目录的 README.md 界定一套数据；系统找到这个边界后不再把其子目录拆成独立数据集。教师在“数据管理 → 数据集登记与审核”刷新扫描、核对 README、登记并授权。只需按网页流程操作，不需每加一份数据重装服务。维护者修改 README 后刷新扫描同步说明。

README 可用以下格式填写标签和 Markdown 说明：

```md
---
tags: [教学, 分类]
---
# 数据集名称
说明用途、文件结构、字段、单位、读取方式与使用条件。
```

数据读取报错、平台安装更新或服务器故障由管理员处理。学生可保存报错发反馈，不自行修改系统权限、受保护运行库或中央数据库。
